# Использование и сборка библиотеки 

В данном разделе рассматриваются требования, процесс сборки и подключение библиотеки к вашему проекту на различных платформах. При этом важно понимать, что процесс подключения библиотеки максимально упрощён, но различается в зависимости от платформы из-за разных технологий сборки ядерного кода.

## Сборка библиотеки

В папке `lib` находится файл `knet.c`, который объединяет все необходимые исходники библиотеки.   Этот файл подключается в пользовательском Makefile для включения всех компонентов библиотеки в сборку.

---

## Подключение библиотеки к вашему проекту

### 1. Заголовочные файлы

Добавьте путь к папке `include/` в `ccflags-y`:
```makefile
ccflags-y += -I KernelSocket-API/include
```

### 2. Пути к внутренним заголовкам
Для корректной компиляции исходников библиотеки необходимо добавить путь к папке `src`:
```makefile
ccflags-y += -I KernelSocket-API/src
```

### 3. Исходные файлы библиотеки
Подключите файл `knet.c` через список объектных файлов вашего модуля:
```makefile
my_driver-y += KernelSocket-API/lib/knet.o
```
### Полный пример пользовательского Makefile
```makefile
KERNEL_VERSION := 6.8.0-101-generic
KDIR := /lib/modules/$(KERNEL_VERSION)/build
PWD := $(shell pwd)

obj-m += my_driver.o

my_driver-y := \
    main.o \
    KernelSocket-API/lib/knet.o

ccflags-y += -I KernelSocket-API/include

all:
	$(MAKE) -C $(KDIR) M=$(PWD) modules

clean:
	$(MAKE) -C $(KDIR) M=$(PWD) clean
```

### Пример использования библиотеки в коде
```c
#include "ksockapi.h"

// ...
```

## Как это работает

### Особенности сборки в Linux (KBUILD)

Система сборки KBUILD требует, чтобы **все исходные файлы модуля компилировались в рамках одной сборочной единицы**. Подключение внешних объектных файлов может привести к ошибкам линковки.

Поэтому все исходники библиотеки объединены в файл `knet.c`, который подключается к вашему модулю и компилируется вместе с ним.

## Сборка библиотеки

### Компиляция `.lib` файла

Откройте решение в папке `lib` и скомпилируйте `.lib` файл под вашу версию Windows. При этом важно, чтобы для данного решения были установлены и подключены все необходимые зависимости. Сделать это можно двумя способами:

1. **Автоматический (рекомендуемый)** — воспользуйтесь модулем [`restore-package`](../../restore-packages/README.md), который скачает все необходимые зависимости в папку `packages`. В этом случае подключение всех зависимостей выполняется автоматически благодаря `Directory.Build.props`, расположенному в корне проекта.

2. **Ручной** — установите все зависимости самостоятельно, скачав их с внешнего источника или через менеджер пакетов NuGet. Однако в таком случае все импорты придётся подключать отдельно вручную.

Готовый `.lib` файл появится на уровне с исходниками сборки.

### Возможные проблемы

#### Ошибка "ValidateNTTargetVersion"

**Симптом**:

```
Невозможно загрузить задачу "ValidateNTTargetVersion" из сборки...
```

**Причина**: Несоответствие версий WDK и ожидаемой версии Visual Studio.

**Решение**: В папке packages найдите файлы:

- `Microsoft.DriverKit.Build.Tasks.17.0.dll`
- `Microsoft.DriverKit.Build.Tasks.PackageVerifier.17.0.dll`

Скопируйте их и переименуйте, заменив 17 на требуемую версию (например, 18).

## Подключение библиотеки к проекту

1. Добавьте путь к папке `include/` в разделе "Дополнительные каталоги включаемых файлов"

2. Добавьте соответсвующий `.lib` файл в "Дополнительные зависимости" компоновщика

4. Так же в дополнительные зависимости, необходимо явно добавить `netio.lib` для корректной работы библиотеки.

Пример использования

```c
#include <ksockapi.h>

// ...
```
