#### Описание архитектурного решения для сборки под Windows

В процессе разработки встал вопрос о том, как правильно собирать библиотеку под Windows. Стандартный CMakeLists здесь не подходит, так как он не поддерживает сборку библиотек, предназначенных для работы с WDK. Поэтому было принято решение полностью отказаться от CMake в Windows-ветке.

В папке bin будут располагаться все основные платформозависимые .lib файлы для прямого подключения в проект Visual Studio в качестве дополнительных зависимостей. Однако, если вам потребуется собрать проект самостоятельно с учетом ваших особенностей, следующий раздел поможет понять архитектуру API, используемые зависимости и причины принятых решений.

#### Подгготовка Visual Studio

Для начала необходимо установить все зависимости для работы с WDK. На момент разработки использовались следующие компоненты из Visual Studio Installer (вкладка "Отдельные компоненты"):

- Комплект разработки драйверов для Windows (WDK)

- Библиотеки C++ с устранением рисков Spectre для x64/x86 (последняя версия MSVC)

#### Настройка проекта

Запустив готовое решение, вы получите все актуальные настройки, необходимые для корректной компиляции статической библиотеки (.lib). Однако ниже дублируются основные шаги для сохранения базы знаний и возможной будущей оценки.

1. Создание проекта

    Был создан проект на основе шаблона KMDF (empty). Данный шаблон содержит все необходимые настройки для компиляции драйверов с расширением .sys. Visual Studio автоматически выставляет нужные флаги компиляции, что позволяет избежать проблем с неопознанными символами из Runtime Checks, которые могли бы возникнуть при использовании CMake.

2. Структура исходного файлоа (all_sources.c)

    Был создан единый исходный файл, в который включены все необходимые .c файлы. Важно отметить, что в итоговой версии отсутствуют файлы Linux-адаптеров, протоколов и common-функций. Это не архитектурное ограничение, а следствие оптимизации: диспетчер на этапе компиляции определяет целевую платформу (Windows или Linux) с помощью макросов, поэтому Linux-заголовки просто не попадают в конечный модуль.

    Ключевой фрагмент, описывающий это поведение:

    ```
    // src/dispatcher/dispatcher.c

    const net_vtable_dispatcher* vtable =
    #ifdef _WIN32
        &windows_vtable;
    #else
        &linux_vtable;
    #endif
    ```

3. Тип конфигурации

    В свойствах проекта необходимо изменить тип сборки с драйвера на библиотеку:
    Свойства конфигурации → Общие → Тип конфигурации → Статическая библиотека (.lib).

4. Подключение WDK и SDK

    Важно отметить, что проект не дублирует NuGet-пакеты с WDK и SDK — они находятся в папке `packages`, расположенной на одном уровне с решением. Рекомендуется указывать пути к этим пакетам с помощью тега `<Import>` в файле `.vcxproj`. Это обеспечивает единую точку управления зависимостями для всех проектов.

5. Возможные проблемы с версиями WDK

    Если после обновления или повтороной установки пакетов в папке packages Visual Studio начинает выдавать ошибки вида:
    ```
    Невозможно загрузить задачу "ValidateNTTargetVersion" из сборки...
    ```
    проблема обычно связана с несоответствием версий. Например, Visual Studio требовал 18-ю версию файлов, а в пакете WDK присутствовали:

    ```
    Microsoft.DriverKit.Build.Tasks.17.0.dll
    Microsoft.DriverKit.Build.Tasks.PackageVerifier.17.0.dll
    ```
    Решение простое: скопировать эти файлы и переименовать, заменив версию 17 на 18 (или на актуальную для вашей среды).

#### Использование собранной библиотеки

После выполнения всех шагов вы получите .lib файл. Для его использования в проекте драйвера:

1. Подключите заголовочные файлы в разделе "Дополнительные каталоги включаемых файлов".

2. Добавьте .lib как дополнительную зависимость в настройках компоновщика.

#### Для кого предназначен этот документ

Данное описание будет полезно в первую очередь разработчикам API, а также тем, кто изучает архитектуру проекта или экспериментирует с библиотекой. Рядовым пользователям оно вряд ли потребуется — для них основным артефактом является готовая .lib библиотека и заголовочный файл.
